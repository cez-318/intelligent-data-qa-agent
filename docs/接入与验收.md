# 接入与验收

## 数据与权限

使用独立测试环境，不覆盖生产库。先核实元数据配置和查询白名单；当前配置是原代码提供的电商星型表，不包含企业人力表。数据仓库账号只授予批准表/视图的SELECT，不授予写入、FILE或管理权限。元数据库和索引构建使用独立管理凭据。

元数据库必须已有原项目4张表：`table_info`、`column_info`、`metric_info`、`column_metric`；模型定义在 `backend/app/models`。可在新建的专用元数据库执行以下初始化（仅创建缺少的表，不清空已有表）：

```powershell
cd backend
../.venv/Scripts/python.exe -m app.scripts.init_metadata --confirm-create-tables
../.venv/Scripts/python.exe -m app.scripts.build_meta_knowledge -c conf/meta_config.yaml
```

第二条会读取白名单列的少量样例和最多1000个去重取值，并写入元数据库、ES和Qdrant。本机Embedding是离线本地模型，不产生云端Embedding调用费用。先确认取值允许进入检索/模型环境。元数据和向量已改为稳定ID/upsert，相同配置可以重复构建，本机验证重复构建后数量不变。但仍不提供删除同步：删除配置字段或别名、收紧授权后不能假设旧索引数据已清除，需规划隔离新索引/受控迁移，不能直接在旧生产索引上重跑后宣称完成清理。

Qdrant集合为 `data-agent-column`、`data-agent-metric`，向量维度必须匹配Embedding。ES索引由 `ES_INDEX` 指定。不要对生产索引做破坏性清空。

## 一条查询的验收

1. 启动 `start_app.cmd`，`/api/health`应显示ready；该检查尚不代表LLM认证通过。
2. 在网页输入令牌和问题，确认出现三路召回、筛选、计划、校验及查询进度。
3. 展开依据，核对指标公式、时间筛选、地区等维度和绑定参数；与人工只读SQL对账。
4. 使用相同问题至少重复3次；记录正确/澄清/失败，而不是只统计有返回值。
5. 验证敏感字段、写SQL、提示注入、未知指标、零基期、无数据、超时和断连；失败不能退回规则或预置答案。
6. 对真实问题集统计结果准确率、澄清率、安全拒绝率、P50/P95端到端时延。测试规模、数据版本、模型名必须一起记录，不能写成未经验证的简历数字。

`tools/check_live.py`只打印请求号、事件类型和耗时，不落盘业务结果；在网页核对实际表格。它只做单次连通性验证，不自动宣称答案正确。

## 发布门槛

当前版本已在原验收环境验证 MySQL 只读账号、真实检索和 DeepSeek 全链路，最新证据见 `reports/稳定性收尾验证报告.md` 与 `reports/真实零售数据评测报告.md`。迁移到新环境后仍需重新验证账号授权、真实业务口径、代表性问题集、数据库超时/断连、多用户隔离和并发压力。

## 本机复验

- `tools/check_database_accounts.py`：只读核验登录和授权。
- `tools/check_local_stack.py`：只读核验样例库、指标编译SQL、三路检索和索引数量，不调用LLM。
- `tools/verify_live_examples.py --confirm-paid-synthetic-test`：7个真实DeepSeek问答；仅允许本机隔离虚构库，可能产生模型费用；输出带时间戳报告保留每轮结果。
- `verify.cmd`：离线回归，不调用真实模型。

发布包默认从 `models/bge-large-zh-v1.5` 只读挂载 Embedding 模型；自定义 ES 镜像必须包含 IK 分词器。镜像使用 `pull_policy: never`，新电脑需先准备对应镜像和模型目录，当前启动脚本不是自动下载安装器。
