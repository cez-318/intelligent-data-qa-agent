# 第三阶段：随机实验效应评估

这是原智能问数应用中的新功能，不是替换原项目的 Demo。页面、服务访问令牌、FastAPI 入口和请求追踪沿用原系统；原零售问数与贡献分解保持独立。新模块从登记数据实时核算，不返回预置效应值，也不在模型失败时冒充问数降级结果。

## 如何使用

1. 按原方式运行 `start_services.cmd`、`start_retail.cmd`，打开 http://127.0.0.1:8000/ 。
2. 刷新页面后，在上方输入 **DATA_AGENT_API_TOKEN**，不是 DeepSeek 密钥。
3. 在“随机实验评估”中选择 Hillstrom 实验，点击“核对实验并估计效应”。
4. 查看两种邮件方案相对不发邮件的购买率、访问率差异，校正后的区间、分母、数据质量和来源；可导出 JSON。

此入口不需要模型生成统计数值，也不需要为每次计算支付模型调用费用。普通聊天暂不自动路由到实验分析；问到没有证据的人力政策因果问题仍应澄清，而不是偷偷换成邮件实验回答。

## 采用的数据及边界

来源是 [Kevin Hillstrom 2008 年实验说明](https://blog.minethatdata.com/2008/03/minethatdata-e-mail-analytics-and-data.html)。发布者说明：64,000 名过去一年内购买过的客户，随机分配到男装主题邮件、女装主题邮件和不发邮件三组，随后跟踪两周。邮件分组表示内容，**不是客户性别**。

下载：`tools/fetch_hillstrom.py`；数据和下载记录位于 `datasets/hillstrom/`。现有文件不自动覆盖。使用发布者可用的原始 HTTP CSV 链接；HTTPS 校验失败时没有禁用证书校验。HTTP 无传输认证，SHA-256 只能固定下载字节，不能当成出版方签名或来源真实性证明。原页面未发现明确的再分发许可，不应自动把完整数据发布到公共仓库；CSV 已在忽略规则中。

数据哈希：`0e5893329d8b93cefecc571777672028290ab69865718020c78c7284f291aece`。

文件无客户 ID、分配日志和逐日时间戳。完全相同行的额外数量为 6,562；不能据此确定重复客户，所以保留，不做会改变随机组构成的自动删除。“每人一行”和完整随访仍依赖发布者说明。保留这些限制后，才可在实验假设成立的条件下作平均效应解读。

## 已实现的方法

- 估计量：全体原始分配对象的意向处理风险差，处理组发生率减对照组发生率；不按访问、转化等处理后变量筛选分母。
- 当前结果：购买率 conversion、访问率 visit；不支持消费金额的连续结果检验。
- 当前比较：2 个处理组 × 2 个结果，共 4 项，全部输出，不按显著性挑选。
- 区间：Wilson/Newcombe 两独立比例之差的近似区间。方法参见 [statsmodels 官方文档](https://www.statsmodels.org/dev/generated/statsmodels.stats.proportion.confint_proportions_2indep.html)。
- 多重比较：Bonferroni，family alpha=0.05，每项 alpha=0.0125，每项名义区间为98.75%，整体名义覆盖目标95%。这是本次固定分析计划，不是声称该历史研究在2008年预注册了本系统的分析。
- 样本分配比例（SRM）：对登记比例作卡方检验，p<0.001 则停止输出效应；通过不等于随机化被证明。
- 处理前平衡：登记的 recency、history、mens、womens、newbie 数值变量，报告标准化均值差，绝对值>0.1 提示检查。仅为诊断，不证明所有混杂均已排除。
- 区间跨0：表述为证据不足，不能表述为“确定无效”。相对提升的对照分母为0时不输出相对提升。

这些是固定终点近似推断，不支持连续窥视、任意事后子组筛选、集群随机化或重复测量。两个邮件组共用对照会使比较相关，但 Bonferroni 不要求各项检验独立；每个风险差仍依赖组间客户独立等假设。

## 安全与扩展

登记文件：`backend/conf/experiments.json`。API 只接收 `experiment_id`，不接受任意路径、SQL、临时随机化声明、结果筛选、置信水平或自造公式。任意追加字段按422拒绝。沿用服务令牌和请求限流，未授权返回401。

后端核对字段顺序、文件哈希、行数、分组、二元结果及处理前数值。缺失结果不填0，未知组、不完整导出、非法计数和样本不足都拒绝。统计本身可在 LLM 不可用时执行，因为这是用户明确选择的独立功能，不是问数失败后的备用答案。

当前登记文件是运维控制面，不开放给普通用户修改。将来接入新实验，需要维护者审查单位、随机机制、分配比例、完整样本、观察窗口和授权来源，再登记；不能只是把普通业务表标记成 randomized。接入人力数据还需要原项目尚缺的员工级授权、审计和隐私治理。

## 可复现验证

项目根目录用 `.venv\Scripts\python.exe` 执行：

```text
python tools/verify.py
python tools/verify_experiment.py
python tools/verify_experiment.py --api
python -m pip install -r requirements-audit.txt
python tools/build_experiment_audit.py
```

独立核对使用 DuckDB 直接聚合原始 CSV，再用 statsmodels 计算区间，不复用生产聚合器或区间函数。程序行为测试覆盖拒绝、安全和数值边界。执行记录在 `reports/experiment_*.json`，可执行审计在 `reports/experiment_audit.ipynb`。

## 仍未完成的能力

没有实现任意观察性数据因果发现、DID、倾向得分、个人处理效应、自动政策推荐或因果机制识别。不能用这次邮件实验直接解释用友人力部门的政策效果。真正接入需要具体干预与对照设计；若仅有政策前后数据而无可辩护的识别假设，应继续拒绝因果断言。

原来零售问数在首轮留出测试出现过检索中断，重启后复测通过，但根因仍未确认。本轮新增统计入口不经过该检索链，不能据此宣称旧检索故障已修复。
