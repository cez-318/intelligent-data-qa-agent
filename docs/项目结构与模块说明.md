# 项目结构与模块说明

## 1. 系统目标

系统把自然语言业务问题转换成受控的数据查询或明确的澄清结果。核心目标不是让大模型自由生成任意SQL，而是让模型负责理解意图，让服务端负责口径、授权、校验和执行。结果同时返回数据、指标解释、SQL、绑定参数和限制说明，便于业务人员与数据人员共同复核。

## 2. 整体调用链

```text
Vue 页面
  -> POST /api/query + Bearer访问令牌
  -> FastAPI QueryService（60秒总预算）
  -> LangGraph 提取关键词
  -> 字段Qdrant / 取值Elasticsearch / 指标Qdrant 三路召回
  -> 合并、授权过滤、表与指标筛选
  -> DeepSeek生成结构化决策
  -> 服务端指标编译或受控明细SQL
  -> SQL AST、白名单、LIMIT与EXPLAIN校验
  -> MySQL只读执行；失败时最多3次受控修复并重新校验
  -> 描述性比较或贡献分解
  -> SSE持续输出进度、结果、依据或澄清
```

随机实验走独立接口：登记实验ID -> 校验固定文件和哈希 -> 聚合处理组/对照组 -> 固定统计算法计算风险差和校正区间 -> 返回假设、诊断及限制。它不会在普通问数失败时充当备用答案。

## 4. 后端 `backend/app`

### 4.1 应用入口与生命周期

- `backend/main.py` 创建 FastAPI 应用、注册问数与实验路由、挂载前端构建目录并提供健康检查。
- `app/core/lifespan.py` 在启动阶段读取配置、初始化MySQL/ES/Qdrant/Embedding依赖，并在关闭时释放客户端。
- `app/api/dependencies.py` 负责访问令牌、限流和服务就绪检查；页面令牌与模型API Key是两套不同凭据。

### 4.2 LangGraph 编排

- `app/agent/graph.py` 是主状态图，三路召回从同一关键词节点并发分叉，全部完成后才能进入合并节点。
- `app/agent/state.py` 定义问题、召回结果、决策、SQL、校验次数和最终结果等状态。
- `app/agent/context.py` 注入依赖，测试可以替换为受控适配器，生产入口仍使用真实服务。
- `app/agent/nodes` 每个文件只负责一个阶段：关键词、召回、筛选、上下文、生成、校验、纠错和执行。

### 4.3 数据访问层

- `app/clients` 管理外部客户端的初始化和关闭。
- `app/repositories/qdrant` 查询字段和指标向量。
- `app/repositories/es` 查询业务取值。
- `app/repositories/mysql/meta` 保存表、字段、指标和映射元数据。
- `app/repositories/mysql/dw` 在只读会话中执行已校验SQL、设置超时并限制结果行数。
- `app/models` 与 `app/entities` 分别表示数据库模型和传输对象。

### 4.4 服务层

- `app/services/query_service.py` 为单次请求创建上下文，设置60秒总预算，把图事件编码为SSE；异常只输出白名单错误码、阶段和诊断编号。
- `app/services/meta_knowledge_service.py` 从授权配置构建元数据库、Qdrant和ES索引，使用稳定ID和upsert避免重复构建产生重复记录。

## 5. 增强层 `backend/improved`

| 模块 | 职责 | 关键边界 |
|---|---|---|
| `compiler.py` | 将结构化计划编译为参数化SQL | 指标表达式、关联和强制条件只能来自配置 |
| `guard.py` | AST、表列函数、只读语句和LIMIT校验 | 写SQL、注释、递归CTE、未知列等直接拒绝 |
| `intent_contract.py` | 保证国家等显式实体没有在计划中丢失 | 修复后再次检查，不靠字符串拼SQL |
| `retrieval.py` | 并发召回、授权字段过滤和任务清理 | 每批最多4并发；失败/取消时等待子任务退出 |
| `diagnostics.py` | 阶段超时、有限重试、错误分类和脱敏日志 | 认证、429、非法响应不自动重试 |
| `decomposition.py` | 完整分组贡献与两因素对称分解 | 保留未知组；缺期或零分母不补值 |
| `analysis_queries.py` | 校验分析计划并生成双期及分组查询 | 只允许声明的分析类型和维度 |
| `analysis_execution.py` | 在只读重复读快照内执行分解并守恒核对 | 失败回滚，避免跨时间读取不一致 |
| `experiments.py` | 二元结果风险差、Newcombe区间和多重比较校正 | 固定算法，不由大模型计算 |
| `experiment_registry.py` | 读取登记实验、固定文件、列和设计 | API不能提交任意路径或任意实验设计 |
| `profiles.py` | 在默认样例和零售配置间显式切换 | 只接受固定名称，不接受用户文件路径 |
| `settings.py` | 读取纯 `KEY=VALUE` 配置并检查必需项 | 进程环境优先；错误不回显秘密 |
| `tei.py` | 适配本地TEI Embedding协议 | 校验维度、数值和批次大小 |

## 6. 配置、提示词和评测

- `backend/conf/rag_semantics.yaml`：默认电商样例的指标注册表。
- `backend/conf/query_policy.yaml`：默认允许表、列、函数、行数和超时。
- `backend/conf/meta_config.yaml`：表字段说明、别名、样例和取值检索设置。
- `backend/conf/retail_ii`：106万行公开零售数据的独立命名空间、8项指标与授权。
- `backend/conf/experiments.json`：随机实验文件、哈希、处理组、对照组和结果字段登记。
- `backend/prompts/plan_query.txt`：要求模型输出结构化决策，可返回指标计划、受控明细SQL或澄清；它不是最终安全边界。
- `backend/evaluation`：200题零售冻结集和20题分解冻结集，哈希用于防止评测过程中偷偷改题。

## 7. 前端 `frontend`

- `src/App.vue` 提供服务状态、令牌输入、示例问题、进度、结果表、比较与贡献分解展示。
- `src/ExperimentPanel.vue` 提供登记实验选择、评估请求、效应区间、假设和限制说明。
- `src/queryStream.js` 单独实现SSE解析，支持UTF-8分片、CRLF、多行data、终态检查、2MB上限和reader清理。
- `src/style.css` 负责桌面布局和结果卡片样式。
- `tests/queryStream.test.js` 覆盖正常终态、断流、非法JSON、缺失数据、超大帧和认证错误文案。

前端不会保存DeepSeek API Key。页面输入的是后端访问令牌，只存在当前页面内存，刷新后需要重新填写。

## 9. 报告 `reports`

发布包只保留当前结论、最新全量运行和可重建审计材料。JSON记录每题状态、请求ID、SQL、参数、结果和耗时；Markdown报告解释分母、失败、数据边界和不能得出的结论。覆盖率只针对指定主流程/安全模块，不是整个仓库覆盖率。

## 10. 安全和失败行为

- 查询账号只授予批准仓库的SELECT；元数据库账号与查询账号分离。
- SQL参数与代码分离；授权配置是服务器端事实源。
- 已知连接、502/503/504类临时故障最多重试一次；认证、429和未知异常快速失败。
- Embedding阶段25秒、检索阶段12秒、请求全程60秒；前端接收限时70秒。
- 日志只记录阶段、错误码、次数、耗时和诊断编号，不记录原始问题、SQL结果、URL、异常正文或凭据。
- 任一检索子任务失败或外层取消时，其余子任务会被取消并等待退出，避免连接继续占用。

## 11. 已知限制

- 指标编译支持单一事实表、批准的多对一维度、AND过滤、分组、排序、多指标和两期比较；不支持任意OR、多事实表自动推理或任意新公式。
- 当前服务令牌不是企业SSO或部门RBAC。
- 默认部署依赖本地自定义ES镜像和Embedding模型，发布包不携带它们。
- 200题是模板化开发/留出实例，不是独立业务人员盲测。
- 贡献分解只解释算术构成；只有登记的随机实验数据才能进入实验因果模块。
