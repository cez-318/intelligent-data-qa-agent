# 本机账号与密码

这三项不是从DeepSeek平台获取的。发布包中没有预置值；运行 `tools/configure_local_credentials.py --prepare` 后由本机安全随机数生成器创建，值保存在 `backend/.env`，不要发到聊天、截图或提交Git。

| 配置项 | 用途 | 查看位置 |
|---|---|---|
| DATA_AGENT_API_TOKEN | 访问智能问数接口的令牌 | `.env`同名项；网页“服务访问凭据”复制等号后的完整值 |
| META_DB_PASSWORD | 元数据库metadata_owner账号密码 | `.env`同名项；后端自动读取，不用在网页填写 |
| DW_DB_PASSWORD | 数据仓库qa_readonly账号密码 | `.env`同名项；后端自动读取，不用在网页填写 |

与DeepSeek API Key分开，三个值互不复用。`LLM_API_KEY` 需要使用者自行填写。任何曾出现在聊天中的旧密钥都应在控制台撤销，换新后仅在本地更新，重启后端生效。

## 本次隔离范围

- 独立容器：`qa-opt-mysql`，只绑定 `127.0.0.1:13306`。
- 独立持久卷：`intelligent-qa-optimized_qa_mysql_data`。
- 元数据库meta：账号只获该库的读写和建表等权限。
- 数据仓库dw：qa_readonly只有SELECT权限，无写入和授权权限。
- 原来名为mysql的容器未启动、未改密、未删除数据。
- 此次新建数据库用于优化版；未复制原库业务数据，已导入原电商表结构的5条虚构订单用于验证，不是公司真实业务数据。
- 配套容器为qa-opt-elasticsearch、qa-opt-qdrant、qa-opt-embedding，只绑定本机独立端口19200、16333、18080；原同类容器及数据未改动。

`.secrets`保存初始化SQL和root密码，仅用于这一套本机数据库，已排除Git提交，并为当前Windows账户授予读取权限。不要分享这些文件。应用不使用root账号。

服务通过Docker Desktop启动；以后执行 `start_services.cmd` 启动数据库和检索服务，再执行 `start_app.cmd`。向量模型冷启动需要等待。数据保存在独立卷中，关闭容器不会清空数据。不要执行 `down -v` 或删除卷。

修改`.env`密码不会自动修改MySQL中的密码；不要随意改掉已生成值。初始化SQL仅在空数据卷首次启动执行，不用于重置账号。

可在项目根目录运行 `.venv/Scripts/python.exe tools/check_database_accounts.py`，验证两个账号能登录以及只读授权；不会输出密码。后端修改配置后必须重启。
